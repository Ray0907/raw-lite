# raw-lite Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved RAW-to-JPEG core library first, then a minimal Tauri v2 desktop shell that drives it.

**Architecture:** A Cargo workspace contains a UI-independent `raw-lite-core` crate and a `raw-lite-app/src-tauri` crate. The core recursively discovers supported RAW files, runs a caller-selected `dcraw`/`dcraw_emu` executable once per file, decodes PNM stdout, resizes without upscaling, creates collision-safe JPEGs without overwriting, and reports progress plus per-file failures. The Tauri command runs that synchronous work off the async runtime, emits progress, prevents overlapping batches, and opens the chosen output folder after completion; a vanilla TypeScript frontend supplies the single-screen flow.

**Tech Stack:** Rust 2024, Cargo workspace, `image` (PNM/JPEG only), Tauri 2, vanilla TypeScript/Vite, Tauri dialog/opener plugins.

### Task 2: RAW decode, resize, JPEG write, and batch resilience

**Acceptance criteria**
- The production decoder command is `dcraw`-compatible and consumes binary PNM from stdout.
- Long edge is bounded by `max_dimension`; smaller images are not enlarged.
- JPEG quality is passed to the encoder.
- Existing output files are never overwritten; collisions receive a numeric suffix.
- Decoder/image/write failure is recorded per file and later files continue.
- Progress is emitted exactly once per processed input.
- No partial JPEG remains after failure.

## Chunk 2: `raw-lite-app`

### Task 3: Tauri backend bridge

**Acceptance criteria**
- One async `start_conversion` command maps frontend arguments into the core API.
- Synchronous process/image work uses `spawn_blocking`.
- Overlapping batches are rejected and the busy flag resets on every exit path.
- `conversion-progress` payloads contain processed, total, current filename, and success state.
- Completion returns a serializable summary and opens the output folder through the Rust opener API.
- Decoder resolution prefers `RAW_LITE_DCRAW`, then the bundled executable beside the app, then `dcraw_emu`/`dcraw` on `PATH`.

### Task 4: Single-screen frontend

**Acceptance criteria**
- Startup asks for an output directory; cancel leaves a clear button to choose one later.
- Native Tauri drag/drop accepts files and folders and automatically invokes conversion.
- Progress displays `N / total` and current filename.
- Advanced controls default to 2000 px and quality 75 and remain optional.
- Completion shows success count and failed filenames/reasons; the backend opens the output directory.
- Controls are disabled while converting and accessible status text uses `aria-live`.
